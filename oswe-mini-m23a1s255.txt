## How the fix works — technical summary 💡

- App-level hard limit: app.config['MAX_CONTENT_LENGTH'] = 10 MB
  - This causes Werkzeug to short-circuit overly large requests early.
- Pre-processing validation:
  - Use Content-Length when present, otherwise determine stream size
    without loading the entire payload into memory (reads up to the limit).
- Fail-fast and informative:
  - Oversized uploads → HTTP 413 with JSON error explaining the limit
  - Missing/invalid file → HTTP 400 with JSON error
- Robust exception handling:
  - MemoryError → caught and returned as HTTP 413 (no 500 crash)
  - UnidentifiedImageError → 400 (invalid image)
  - Generic exceptions → 500 with non-revealing JSON
- Safe defaults:
  - Quality parameter sanitized (bounded)
  - Mode normalization (convert non-RGB to RGB before saving)

Comments in app.py explain the security/safety rationale.

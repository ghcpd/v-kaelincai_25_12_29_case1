## Phase 3: Implement Code Fixes in src\app.py

Apply these specific fixes to create a memory-safe implementation:

### 3.1 Flask Configuration (Defense Layer 1)
- Set `app.config['MAX_CONTENT_LENGTH'] = 16 * 1024 * 1024` (16MB)
- This provides Flask-level request size protection

### 3.2 Pre-Processing File Size Validation (Defense Layer 2)
- Define `MAX_FILE_SIZE = 10 * 1024 * 1024` or `15 * 1024 * 1024` (10-15MB) constant
- Check file size using `file.content_length` or by reading stream before image processing
- Return HTTP 413 with JSON `{"error": "File too large", "max_size_mb": X}` if exceeded

### 3.3 Image Dimension/Pixel Validation (Defense Layer 3)
- Define `MAX_PIXELS = 25_000_000` (25 million pixels) limit
- After opening image, check `image.width * image.height`
- Return HTTP 413 with JSON `{"error": "Image dimensions too large"}` if exceeded

### 3.4 Exception Handling (Defense Layer 4)
Wrap image processing code in try-except blocks:
- Catch `MemoryError`: return HTTP 413 with JSON `{"error": "Memory limit exceeded"}`
- Catch `PIL.UnidentifiedImageError`: return HTTP 400 with JSON `{"error": "Invalid image file"}`
- Catch PIL `DecompressionBombError`: return HTTP 413 with JSON error
- Catch generic `Exception`: log error, return HTTP 500 with JSON `{"error": "Processing failed"}`

### 3.5 Error Handlers
Add Flask error handlers:
```python
@app.errorhandler(413)
def request_entity_too_large(error):
    return jsonify({"error": "Request too large"}), 413
```

### 3.6 Code Comments
Add inline comments explaining:
- Each defense layer and its purpose
- Why specific limits were chosen (10-15MB file, 16MB request, 25M pixels)
- How exceptions are caught and transformed into HTTP responses
- Security rationale for each validation step
